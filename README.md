# mmcli

Простой консольный клиент Mattermost. Stateless: каждый запуск — отдельный
процесс, который ходит к серверу по REST. Секреты (пароль, кешированный
session-токен) хранятся в системном keyring (Secret Service на Linux, Keychain на macOS).

## Установка

```sh
brew tap esivres/mmcli https://github.com/esivres/mmcli
brew install --cask esivres/mmcli/mmcli
```

На Linux имя `mmcli` занято ModemManager (`/usr/bin/mmcli`): в скриптах
вызывайте `$(brew --prefix)/bin/mmcli`.

## Сборка

```sh
go build -o mmcli ./cmd/mmcli
```

Релиз: пуш тега `v*` — GoReleaser собирает бинарники и обновляет
`Casks/mmcli.rb`.

## Аутентификация

Логин по login_id + паролю; полученный session-токен кешируется в keyring и
переиспользуется между запусками. При истечении токена (401) клиент
автоматически перелогинивается один раз.

```sh
# пароль из stdin (предпочтительно)
printf '%s' "$PASSWORD" | mmcli login \
  --context work \
  --url https://mm.example.com \
  --login-id me@example.com \
  --team myteam \
  --password-stdin
```

Источник пароля при login (по приоритету): `--password` → `--password-stdin`
→ `$MMCLI_PASSWORD` → строка из stdin.

### Bot account

Бот не может войти по паролю — только по personal access token. Токен
проверяется при login (`/users/me`), хранится в keyring; перелогина нет,
отозванный или истёкший токен — ошибка.

```sh
printf '%s' "$BOT_TOKEN" | mmcli login \
  --context bot \
  --url https://mm.example.com \
  --team myteam \
  --token-stdin
```

## Контексты

Несколько серверов хранятся как именованные контексты в
`$XDG_CONFIG_HOME/mmcli/config.json` (только не-секретные поля).
`login` делает контекст текущим, только если текущего ещё нет или передан
`--use`: добавление второго контекста (например, бота) не перенаправляет
команды без `--context`.

```sh
mmcli context list
mmcli context current
mmcli context use work
mmcli logout --context work   # стирает токен и пароль из keyring
```

## Чтение

```sh
mmcli get <permalink|post_id>            # один пост
mmcli get <permalink|post_id> --thread   # весь тред
mmcli thread <permalink|post_id>         # то же, что get --thread
```

Принимаются permalink (`https://host/<team>/pl/<id>`) и голые 26-символьные ID.

## Поиск

Флаги собираются в search-модификаторы Mattermost (`in:`, `from:`, `after:`,
`before:`), к ним добавляется свободный запрос.

```sh
mmcli search "релиз" --channel ops --from alice \
  --after 2026-01-01 --before 2026-02-01 --limit 50
```

Сервер отдаёт не больше 100 результатов на запрос, поэтому search повторяет
запрос всё дальше в прошлое (`before:` по дате самого старого результата).
Если выдачу обрезал `--limit` (по умолчанию 50) или за один день больше 100
результатов, в stderr выводится предупреждение; `--all` снимает лимит.
Даты `--after`/`--before` — дни по UTC.

Команда автоматически читается на уровне той team, что задана `--team` или
дефолтной для контекста.

## Ответ и публикация

```sh
mmcli reply <permalink|post_id> "текст ответа"   # тред: отвечает в корень нити
mmcli post  <channel|~channel|channel_link> "текст"  # новое сообщение в канал
mmcli post  @username "текст"                   # личное сообщение (team не нужна)
```

## Вложения

```sh
mmcli file search "инцидент" --ext pdf --after 2026-09-01   # поиск файлов (имя и содержимое)
mmcli file get  <file_id>            # скачать; путь в выводе
mmcli file text <file_id>            # скачать и извлечь текст
```

У постов вложения перечислены в поле `files`. `file text` понимает текст и
логи, docx, xlsx, pdf (нужен `pdftotext` из poppler), zip (с лимитами на
размер, число файлов и вложенность; пропущенное перечисляется). Длинный текст
обрезается посередине с пометкой. Картинки не распознаются (OCR нет): их
нужно смотреть самим через `file get`.

## Поток событий

```sh
mmcli stream --context work --context bot --mention --dm
```

Держит WebSocket на каждый контекст и печатает по строке JSON на событие
(`posted`, `post_edited`, `post_deleted`) до Ctrl+C. Одно событие, увиденное
несколькими контекстами одного сервера, склеивается в одну строку через
`--merge-window` (1.5 с): `contexts` — кто его видит и может ответить,
`mentions` — чей пользователь упомянут. Фильтры `--mention`, `--dm`,
`--channel` (URL-имя канала, не `@user`) объединяются по ИЛИ; без фильтров —
все посты. Правки и удаления проходят вслед за своим постом, если его вывел
этот же запуск за последние сутки. Строки выходят
в порядке поступления. Служебные строки: `connected`, `disconnected`, `gap` —
события потеряны (сервер не смог возобновить соединение или пропустил
номера). Обрыв определяется и по отсутствию ответа на ping; после успешного
возобновления без пропущенных событий `connected` выходит через ~2 с.
При сильной задержке сети `gap` может прийти
уже после `connected`. Отклонённый самим Mattermost токен или логин —
окончательный отказ: если отклонена первая же попытка, `stream` сразу
завершается с ошибкой; иначе печатает `failed` и завершается с ненулевым
кодом, когда не осталось живых контекстов.

## Вывод

По умолчанию — компактный JSON (потребитель — автоматизация). `--pretty` —
форматированный JSON. Посты разворачиваются в плоский вид с ISO-временем,
username и каналом (`channel`: имя канала, `@user` для лички, название для
группового чата; нет поля — канал не удалось определить) вместо сырых ID;
тред/поиск отдаются в хронологическом порядке (старые сверху).

## Замечание про архитектуру

Это намеренно CLI без демона: все команды, кроме `stream`, — request/response.
`stream` держит соединение только пока запущен и не хранит состояние между
запусками.
